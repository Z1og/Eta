# 规范检查

1. 确定项目根：从本轮涉及文件路径向上查找包含 `.trellis/` 的目录；
   找不到则告知用户该项目尚未初始化 Trellis，然后按普通代码检查继续。
2. 读取 `.trellis/spec/` 下全部 spec 文件。
3. 确定检查范围：本轮对话中新建或修改的文件；用户指定了文件时以指定为准。
4. 逐条对照 spec 检查，用表格输出：规范点 | 状态（符合/偏离/不适用）| 位置 | 说明；
   只列与本次改动相关的规范点，不全文复述 spec。
5. 发现偏离时：格式、命名等可安全自动修复的先修复再报告；
   涉及行为或架构的只报告不改，给出修改建议等用户决定。
6. 若发现 spec 本身已过时（代码与规范系统性不一致），提醒用户说「更新规范」沉淀现状。
