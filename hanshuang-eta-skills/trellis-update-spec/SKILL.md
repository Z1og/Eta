# 沉淀规范

1. 确定项目根：从本轮涉及文件路径向上查找包含 `.trellis/` 的目录；找不到则告知用户先「初始化 trellis」。
2. 回顾本轮对话：用户纠正过什么、明确了什么约定、采用了什么新做法。逐条列出候选约定，
   过滤掉一次性的、与本项目无关的、纯临时调试的内容。
3. 候选为空时直接告知没有值得沉淀的内容，不强行写入。
4. 把每条约定合并进对应的 spec 文件：优先编辑已有章节、避免重复，确实出现新类别才建新文件；
   保持每个文件 60 行以内，超出时精简合并旧条目，不无限追加。
5. 在 `.trellis/workspace/journal-<YYYYMMDD>.md` 追加一行：`- HH:mm 更新规范：<变更摘要>`。
6. 向用户展示改动摘要：改了哪个文件、新增或修改了哪几条约定。
